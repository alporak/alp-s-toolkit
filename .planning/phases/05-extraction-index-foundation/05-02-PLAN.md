**Schema (created in `startup()`, NOT in `_get_db()` — the DB file must exist with tables before first use):**

The `startup()` method follows competence.py lines 1037-1093 exactly:

1. Acquire `_db_lock`.
2. Open connection via `_get_db()`.
3. Create `sync_state` table: `CREATE TABLE IF NOT EXISTS sync_state (key TEXT PRIMARY KEY, value TEXT)`.
4. Check current schema version: `SELECT value FROM sync_state WHERE key = 'schema_version'`.
5. If version matches `SCHEMA_VERSION` → close and return (no migration needed).
6. If version doesn't match (or first run), execute the full schema DDL:

```sql
CREATE TABLE IF NOT EXISTS doc_metadata (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    repo TEXT NOT NULL,
    relative_path TEXT NOT NULL,
    full_text TEXT NOT NULL DEFAULT '',
    sha256 TEXT NOT NULL DEFAULT '',
    encoding TEXT NOT NULL DEFAULT 'utf_8',
    needs_ocr INTEGER NOT NULL DEFAULT 0,
    last_extracted TEXT NOT NULL DEFAULT '',
    UNIQUE(repo, relative_path)
);

CREATE VIRTUAL TABLE IF NOT EXISTS doc_search_fts USING fts5(
    full_text,
    content='doc_metadata',
    content_rowid='id',
    tokenize='unicode61'
);

CREATE INDEX IF NOT EXISTS idx_doc_metadata_sha256 ON doc_metadata(sha256);
CREATE INDEX IF NOT EXISTS idx_doc_metadata_repo ON doc_metadata(repo);

INSERT OR REPLACE INTO sync_state (key, value) VALUES ('schema_version', '1');
```

7. Commit, close connection, log success.
8. If migration fails → log warning but don't crash (wrap entire startup in try/except).

IMPORTANT schema design notes:
- `UNIQUE(repo, relative_path)` ensures one row per file — Phase 6 uses INSERT OR REPLACE for upserts.
- `sha256` column supports INDEX-03 (incremental update fingerprinting). Phase 6 compares old/new hashes.
- `needs_ocr` is INTEGER (0/1 boolean — SQLite has no native boolean).
- FTS5 uses `content='doc_metadata'` and `content_rowid='id'` — content-less mode. The FTS5 virtual table stores ONLY the inverted index. When Phase 6 searches, `snippet()` reads full text from doc_metadata. When Phase 6 indexes, INSERT into doc_search_fts with full_text triggers index building on the FTS5 side.
- `tokenize='unicode61'` — standard tokenizer with unicode support, handles English text well.

@app.get("/api/doc_search/status")
async def doc_search_status():
    """Return plugin health and schema version."""
    try:
        ver = _db_get("schema_version")
        return {
            "status": "ok",
            "schema_version": ver or "unknown",

        return {
            "status": "error",
            "schema_version": "unknown",

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → /api/doc_search/status | Public endpoint returning schema version (low risk — informational only) |
| Plugin startup → SQLite schema creation | DDL execution could fail on disk issues or permission errors |
| Test fixtures → extractors | Test-created XML/DOCX/PDF files exercise extraction path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04 | Denial of Service | startup() schema migration | mitigate | DDL execution wrapped in try/except — schema init failure logs warning but does not crash the plugin or the FastAPI app. Plugin returns `schema_version: "unknown"` in status if DB init failed. |
| T-05-05 | Information Disclosure | /api/doc_search/status | accept | Returns only `status` and `schema_version` — no file paths, no document content, no DB connection strings. Low-value informational endpoint. |
| T-05-06 | Elevation of Privilege | SQLite file permissions | accept | doc_search.db created by the app process in `app/plugins/` — inherits process file permissions. Same risk profile as existing `competence_cache.db`. Accepting because this is an internal tool, not a multi-tenant SaaS. |
| T-05-07 | Tampering | FTS5 virtual table | mitigate | content-less mode (`content='doc_metadata'`) prevents direct content injection into FTS5 index — all content must go through doc_metadata first. UNIQUE(repo, relative_path) prevents duplicate entries. |
| T-05-08 | Information Disclosure | test fixtures in tests/ | accept | Tests create minimal fixture files with innocuous content ("Hello world", "Node Zero"). No real document data is committed to the repo. Temporary files cleaned up by pytest tmp_path. |
</threat_model>
