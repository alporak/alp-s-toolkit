## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API response → DOM | Search results, preview text, repo names, filenames cross from server to browser DOM — must be rendered safely |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Injection (XSS) | doc_search.js — result rendering, preview rendering | mitigate | All user-supplied content (filenames, snippets, repo names, preview text) rendered via `textContent` or `document.createTextNode()`. Search term `<mark>` highlights built via `document.createElement("mark")` + manual text splitting — zero `innerHTML` for any data from API responses. Only exception: SVG icons from `core.js` `icons` object (trusted, static). Per UI-11 |
| T-07-02 | Injection (XSS) | doc_search.js — repo scope indicator | mitigate | Repo names from `GET /api/doc_search/repos` rendered via `textContent` only. Color-coded badge styling applied via inline `style` attributes on elements, not via HTML string concatenation |
| T-07-03 | Information Disclosure | doc_search.js — preview endpoint path construction | mitigate | Preview path constructed via `encodeURIComponent(result.repo)` and `encodeURIComponent(result.path)` — no raw path insertion into URL strings. Server-side path traversal protection (NFR-13) is the primary defense; client-side encoding is a defense-in-depth measure |
| T-07-04 | Denial of Service | doc_search.js — debounce timer / polling interval | accept | 250ms debounce prevents request flooding. Sync polling at 2s intervals is low-impact. No risk of client-side DoS from these patterns |
| T-07-05 | Tampering | doc_search.js — AbortController state | accept | AbortController is used only for request cancellation on the client side — no mutable shared state that an attacker could corrupt. Aborted requests are silently discarded |

All threats with disposition "mitigate" are addressed through the implementation patterns specified in the task actions above. No threats require acceptance by the user at this phase (this is a frontend-only plan consuming already-secured backend APIs).
