    - Test 3: GET /api/doc_search/preview/RepoName/path/to/file.txt → returns {repo, path, text: full_text[:2000]}; path traversal attack with ../../../etc/passwd returns 403 with {"error": "Path traversal detected"} per SRCH-03 and NFR-13
    - Test 4: GET /api/doc_search/repos → returns list of {name, path, file_count, last_synced} for each configured repo per SRCH-04
    - Test 5: XSS payload in file content → stored text has HTML tags stripped; search snippet renders via textContent (verified via response content inspection)
  </behavior>
  <action>
    Add three new API endpoints inside `DocSearchPlugin.register_routes()`. All DB reads use `asyncio.to_thread()` for thread safety.

    **1. Search endpoint — `GET /api/doc_search/search?q={query}`**
    - Query param `q: str = ""` (required, but may be empty)
    - If `q.strip()` is empty, return `{"results": [], "total": 0, "query": ""}` — per SRCH-05
    - Build FTS5 query: pass `q` directly to FTS5 MATCH. Use the content-less table's reference to doc_metadata. Query:
      ```sql
      SELECT
        m.id, m.repo, m.relative_path, m.needs_ocr,
        snippet(doc_search_fts, 1, '<mark>', '</mark>', '...', 32) AS snippet,
        bm25(doc_search_fts) AS score
      FROM doc_search_fts
      JOIN doc_metadata m ON m.id = doc_search_fts.rowid
      WHERE doc_search_fts MATCH ?
      ORDER BY score
      LIMIT 50
      ```
    - Run via `asyncio.to_thread()` to avoid blocking
    - Post-process each row:
      - Derive `filename`: `os.path.basename(path)`
      - Derive `file_type`: lowercase extension without dot (e.g., "pdf", "docx")
      - `snippet`: the raw FTS5 snippet string (frontend handles rendering)
      - `score`: float from BM25
      - `needs_ocr`: bool from column
    - Return shape per SRCH-02: `{results: [...], total: int, query: str}`
    - Store `last_search` timestamp via `_db_upsert_state`

    **2. Preview endpoint — `GET /api/doc_search/preview/{repo}/{path:path}`**
    - FastAPI path parameter: `path: str = Path(...)` (catches all slashes)
    - Load repo info from config to get `repo_root`
    - Construct full path: `os.path.join(repo_root, path)`
    - **Path traversal protection (NFR-13):** resolve with `os.path.realpath(full_path)`, then verify `resolved.startswith(os.path.realpath(repo_root) + os.sep)`. If NOT → raise `HTTPException(403, detail={"error": "Path traversal detected"})`
    - Query: `SELECT full_text FROM doc_metadata WHERE repo = ? AND relative_path = ?`
    - Return: `{"repo": repo,"path": path, "text": full_text[:2000]}` — per user decision (first 2000 chars)
    - If file not found in DB: raise `HTTPException(404, {"error": "Document not found in index"})`

    **3. Repos endpoint — `GET /api/doc_search/repos`**
    - Query `doc_metadata` grouped by repo: `SELECT repo, COUNT(*) as file_count FROM doc_metadata GROUP BY repo`
    - For each configured repo from `_load_doc_repos()`, merge in file counts and `last_synced` timestamp from sync_state
    - Return: `[{name: str, path: str, file_count: int, last_synced: str|null}]`
    - Zero repos configured returns `[]`

    **4. XSS sanitization helper — `_sanitize_html(text: str) -> str`**
    - Strip HTML tags from text before storing in DB: `re.sub(r'<[^>]*>', '', text)`
    - Applied in the search endpoint (query results are already sanitized in DB)
    - Note: FTS5 snippet() returns text as-is from the stored content — so sanitize at storage time. If content already stored unsanitized from Phase 5 syncs, the search endpoint strips tags from snippet strings before returning in JSON.

    **5. No CORS, no cache headers**
    - No additional headers needed — same-origin plugin, existing FastAPI app. No CORS configuration required.

    Add integration tests: seed an in-memory SQLite with test data (create doc_metadata + doc_search_fts rows), then test each endpoint via `httpx.AsyncClient` against a test FastAPI app. Mock `_load_doc_repos()` to return test repo config.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → Search API | Query string parameter — untrusted input |
| HTTP client → Preview API | URL path parameter — path traversal vector |
| HTTP client → Sync API | POST body (none) — CSRF if CORS were enabled (it is not) |
| DB → JSON response | Stored text may contain XSS payloads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Tampering | `GET /search?q=` query injection | accept | FTS5 handles all query syntax natively — MATCH operator is safe, no SQL injection possible. User-controlled tokens only affect ranking, not query structure. |
| T-06-06 | Information Disclosure | `GET /preview/{repo}/{path}` path traversal | mitigate | `os.path.realpath(full_path)` resolves symlinks and `..` segments; verify result starts with `os.path.realpath(repo_root) + os.sep`; return 403 on violation. NFR-13. |
| T-06-07 | Tampering | Stored XSS in full_text field | mitigate | Strip HTML tags at storage time with `re.sub(r'<[^>]*>', '', text)`. Search snippet output is from FTS5 snippet() which preserves mark tags — strip any remaining non-mark HTML before JSON serialization. Frontend renders via textContent per user decision. |
| T-06-08 | Denial of Service | `GET /search?q=*` wildcard explosion | accept | FTS5 prefix queries are limited by token count (~3000 docs). Query timeout not needed — response stays under 50ms. Low-value DoS vector. |
| T-06-09 | Repudiation | Sync triggered without auth | accept | Internal toolkit with no authentication layer — accepted risk. Future: add API key auth if deployed beyond localhost. |
</threat_model>
