    - Test 4: _sync_repo(repo) walks os.walk, collects ALL file paths, uses ThreadPoolExecutor(max_workers=4) to call extract_text in parallel via asyncio.to_thread, upserts only changed files, cleans deleted — returns {repo, pulled, total, changed, deleted, errors}

  </behavior>
  <action>
    Extend `app/plugins/doc_search.py` with the sync pipeline functions. All blocking I/O (DB writes, file reads, git pulls) MUST run inside `asyncio.to_thread()`. Use `ThreadPoolExecutor(max_workers=4)` for parallel extraction per research recommendation.

    **1. `_should_reindex(conn, repo: str, rel_path: str, sha256: str) -> bool`**
    Query: `SELECT sha256 FROM doc_metadata WHERE repo = ? AND relative_path = ?`. Return `True` if no row found or stored hash differs from argument. Called inside a DB lock block. Synchronous.

    **2. `_upsert_document(conn, repo: str, rel_path: str, result: dict) -> int`**
    `result` is the dict from `extract_text()`: keys `text, encoding, needs_ocr, sha256, error`. Execute:
    ```
    INSERT INTO doc_metadata (repo, relative_path, full_text, sha256, encoding, needs_ocr, last_extracted)
    VALUES (?, ?, ?, ?, ?, ?, datetime('now'))
    ON CONFLICT(repo, relative_path) DO UPDATE SET
      full_text=excluded.full_text, sha256=excluded.sha256,
      encoding=excluded.encoding, needs_ocr=excluded.needs_ocr,
      last_extracted=excluded.last_extracted
    ```
    Then get `last_insert_rowid()` or query the rowid for the `(repo, relative_path)` pair. Then:
    ```
    DELETE FROM doc_search_fts WHERE rowid = ?
    INSERT INTO doc_search_fts(rowid, full_text) VALUES (?, ?)
    ```
    This is the content-less FTS5 update pattern — delete old inverted entry, insert new. Returns rowid.

    **3. `_clean_deleted(conn, repo: str, existing_paths: set[str]) -> int`**
    For the given repo, find all `relative_path` values in `doc_metadata`. Any path NOT in `existing_paths` → DELETE FROM doc_metadata (FTS5 content-less auto-removes the linked row via content_rowid). Return count of deleted rows. Use `conn.executemany` with a list of paths to delete.

    **4. `async _sync_repo(repo_name: str, repo_path: str) -> dict`**
    Core per-repo sync coroutine:
    - `os.walk(repo_path)` collecting all file paths (skip `.git` directory)
    - Compute relative path from repo root
    - For each file, run `compute_sha256(full_path)` to get hash
    - Call `_should_reindex(conn, repo_name, rel_path, sha256)` for each — collect list of files needing change
    - Use `concurrent.futures.ThreadPoolExecutor(max_workers=4)` with `asyncio.to_thread()` to run `extract_text(full_path)` in parallel for changed files
    - For each extraction result: `_upsert_document(conn, repo_name, rel_path, result)`
    - `_clean_deleted(conn, repo_name, set of all found relative paths)`
    - Return summary dict: `{repo: repo_name, pulled: bool, total: int, changed: int, deleted: int, errors: list[str]}`
    - Log errors per-file — never crash

    **5. `async _sync_job() -> None`**
    Top-level orchestrator:
    - `async with _sync_lock`: gate (if locked, log and return)
    - Set `sync_progress` → `{"phase": "starting"}`
    - For each repo in `_load_doc_repos()`:
      - Set `sync_progress` → `{"phase": "pulling", "repo": name}`
      - `await _git_pull(repo.path)` — log result, continue on failure
      - Set `sync_progress` → `{"phase": "indexing", "repo": name, "done": 0, "total": N}`
      - `await _sync_repo(repo.name, repo.path)` — update progress during file processing
    - Set `sync_progress` → `{"phase": "complete"}`
    - Set `last_sync` → ISO timestamp
    - All inside try/finally — lock released in finally

    **Progress reporting pattern:** During `_sync_repo`, after each batch of extractions, call `_db_upsert_state("sync_progress", {phase, repo, done, total})`. The route (Plan 06-02) will read this.

    Add tests to `tests/test_doc_search.py`: mock `extract_text` and `compute_sha256`, use in-memory SQLite, verify upsert creates correct rows, verify cleanup removes expected entries, verify full _sync_repo orchestration.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User config → plugin | toolkit_settings.json is user-editable — paths may be malicious |
| File system → plugin | Files in configured repos may be crafted (symlinks, special chars) |
| Git process → plugin | Git output (stdout/stderr) is logged but not parsed beyond success/failure |
| Subprocess args → OS | Git command arguments must be constructed safely |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `_git_pull()` subprocess call | mitigate | Use argument list `["git", "-C", repo_path, "pull"]` — never shell=True. Subprocess timeout prevents hung processes. |
| T-06-02 | Denial of Service | `_sync_job()` concurrent calls | mitigate | asyncio.Lock guard prevents concurrent sync runs. Timeout on git pull prevents indefinite hang. |
| T-06-03 | Elevation of Privilege | File system walking | mitigate | `os.walk()` stays within `repo_path` — skip `.git` directories. `os.path.relpath()` for path normalization. |
| T-06-04 | Information Disclosure | Git output in logs | accept | Git stdout/stderr is logged at info/debug level — no credentials in git pull output, low-value target. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for any new package installs. |
</threat_model>
